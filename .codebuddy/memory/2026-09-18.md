## 确认：非 Windows 系统下的图标生成与托盘行为
用户询问“Python 脚本在其他操作系统运行时，图标生成受不受影响”。

实测方法（在 Windows 上模拟，独立子进程：`del ctypes.windll` → `importlib.reload(jusic_tray)` → 再 reload `jusic_gui`）：
- Windows 基线：`IS_WINDOWS=True`、`available()=True`、`icon_image_bytes(32)` = **4264 bytes**（头部 `2800000020000000`）。
- 模拟非 Windows：模块 reload **成功不崩溃** → `IS_WINDOWS=False`、`available()=False`、构造 `TrayIcon` 抛 `RuntimeError("系统托盘仅支持 Windows")`；
  **`icon_image_bytes(32)` 仍生成 4264 字节，且与 Windows 输出逐字节相同**（纯 `math`/`struct` 计算，不调用任何系统 API）。
- GUI 降级：`jusic_gui.TrayIcon` 是占位类 → `_init_tray()` 检测 `available()` 为 False 直接 return，`gui._tray=None`；
  `iconify()` 后 `state=iconic`、`_in_tray=False` ⇒ 窗口正常最小化到任务栏，**绝不会被藏进不存在的托盘而“找不回”**。
- 结论：**图标“生成”跨平台无影响；托盘“注册/显示”仅 Windows**。非 Windows 上程序仍可用（播放/房间/歌词/下载均不依赖托盘），只是最小化=普通最小化。
- 其他既有的平台相关点（非本次改动）：`MpvEngine.find_mpv` 候选路径偏 Windows（`C:\Program Files\MPV Player`、WinGet 目录；Linux 靠 PATH）；`CREATE_NO_WINDOW` 已按 `os.name` 判断；`run.bat` 仅 Windows；`_fatal_error` 的 Win32 弹窗失败会回退 stderr。
- 若要真正跨平台托盘：需分平台实现（Linux AppIndicator/GTK、macOS NSStatusBar，或引入 pystray+Pillow），与“低内存/零额外依赖”定位冲突，当前未做。

## 新增 `publish_release.py`：把 dist 产物发布到 GitHub / Gitee Releases
- 需求：把 `dist\JusicRoomPlayer 1.2.0.exe`（62.1 MB）与 `dist\JusicRoomPlayerPortable_1.2.0.zip`（62.3 MB）上传到两个平台的 Releases。
- 远端（两仓库本无任何 Release）：`origin`=gitee.com:seaworld/JusicRoomPlayer（同时也是 github 的 fetch/push 混配），`github`=github.com:seaworld92/JusicRoomPlayer。脚本用 `git remote get-url` 自动解析 owner/repo，回退内置默认值。
- 脚本（纯标准库 urllib，无 pip 依赖）：读 VERSION → 校验两产物存在 → 生成 Release 说明（附件表 + SHA256 + 上次 tag 以来的 `git log --no-merges` 提交）→ GitHub `POST /repos/{r}/releases` + `uploads.github.com/.../assets?name=`（Bearer token，octet-stream）→ Gitee `POST /api/v5/repos/{r}/releases` + `/releases/{id}/attach_files`（multipart，access_token 走 query）。已存在的 release/同名附件自动复用/跳过，幂等可重跑。
- 参数：`--platform all|github|gitee`、`--version/--tag/--name/--notes/--notes-file/--prerelease/--push-tag/--dry-run/--github-token/--gitee-token`；凭证优先取环境变量 `GH_TOKEN`（或 GITHUB_TOKEN）/`GITEE_TOKEN`。
- 已执行：`git tag -a v1.2.0` 并 push 到 origin(gitee) 与 github 两个远端成功（标签此前不存在）。
- 已执行：**Gitee 端 v1.2.0 Release 发布成功**（release id=1150703，页面 https://gitee.com/seaworld/JusicRoomPlayer/releases/tag/v1.2.0，两个附件均已上传：`JusicRoomPlayer 1.2.0.exe`、`JusicRoomPlayerPortable_1.2.0.zip`）。Gitee API 返回的 `assets[].size` 恒为 0，不能用于校验大小，需按 `browser_download_url` 下载确认。
- 已执行：**GitHub 端 v1.2.0 Release 发布成功**（页面 https://github.com/seaworld92/JusicRoomPlayer/releases/tag/v1.2.0 ，非 draft 非 prerelease，两个附件 state=uploaded）。**GitHub 把附件名的空格自动换成点**：`JusicRoomPlayer 1.2.0.exe` → `JusicRoomPlayer.1.2.0.exe`（65110247 B 完全一致），ZIP 名字本无空格故不变。
- 用户提供凭证的方式记录：用户偏好直接对话贴 token（Gitee 私人令牌 + GitHub `ghp_` classic PAT），本例已用完即弃。**用户曾误以为 PAT 就是 SSH 密钥**，已解释：SSH 密钥只能推 git 对象，Release/附件必须用 PAT 调 REST API。
- 注意：Gitee 单个附件有容量限制（本次 62MB 量级应可通过）；GitHub 上传走 uploads.github.com 需 `Content-Type: application/octet-stream`。
