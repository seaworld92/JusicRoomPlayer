### 关键技术调研结论（重要，供复用）
- 网页版实际后端：`https://tx.alang.run/api`（即 happy.alang.run/modern-ui/ 的 API，前端 backend-adapter.js 中 resolveBaseUrl 固定为该地址）。
- REST：`POST /api/house/search`（匿名，header `AccessToken: token`）返回房间列表；字段 id/name/needPwd/population/desc。
- WSS：`wss://tx.alang.run/api/server/000/<随机会话>/websocket?houseId=..&housePwd=..&connectType=enter`（SockJS websocket transport）。无需 STOMP CONNECT/订阅，连上即收推送，纯监听即可；发送非 sockjs 格式帧会被 1007 关闭。
- 推送帧格式（类 STOMP 自定义）：`a[ "TYPE\ncontent-type:application/json\ncontent-length:N\n\n{json}" ]`。关键事件：MUSIC(data 含真实播放 url/lyric/pictureUrl/id/name/artist/duration)、PICK(点歌队列)、ONLINE、CHAT、NOTICE、ANNOUNCEMENT。
- 关键坑（本项目所在 Windows 环境）：
  - 目标服务器 TLS 拒绝部分 TLS1.3 客户端 → Python 必须固定 TLSv1.2（ssl ctx maximum_version=TLSv1.2），且校验证书失败时降级不校验。
  - 本机存在系统代理 127.0.0.1:10808（注册表），Python 自动探测会致 WS 失败；websockets.connect 需 `proxy=None` 直连。
  - websockets 需 v15 稳定（v17 有 ConnectionLost 回调 bug；参数名 v15/v17 不同：v15 用 additional_headers + proxy=None）。
  - PowerShell 对含中文路径的命令参数编码不稳定 → 用 ASCII 临时目录写 python runner、脚本内用 unicode 路径最稳妥。
  - mpv 已装于 `C:\Program Files\MPV Player\mpv.exe`（winget id shinchiro.mpv 0.41.0）。
- 实测内存：python 播放器进程 37.5MB + mpv 约 53MB ≈ 90MB。

## Bug 修复（同日晚）：关闭 GUI 后 mpv 仍在播放
现象：关闭 ttk 窗口后音乐仍在放（mpv 子进程残留）。诊断与处理：
- 根因：mpv 是独立子进程，若关闭太快、后台 asyncio 线程未及时执行 stop（或进程强退导致 daemon 线程被杀），mpv 不会被自动终止。
- 修复（jusic_core.py / jusic_gui.py）：
  1. RoomClient.stop() 先在**调用方线程同步** `engine.stop()`，再投递 stop/join（不再依赖后台线程时序）；
  2. MpvEngine 内部加 `threading.Lock`，play/stop 共用 `_stop_locked()` 串行化（消除 play 与 stop 跨线程竞态，避免"新 mpv 逃过 stop"）；
  3. GUI `_on_close` 先 engine.stop 再 client.stop；`main()` mainloop 结束后的 finally 再兜底清理一次。
- 验证：播放中关窗（按 PID 探测）→ 进程已死；连上后立即关窗 → 无 mpv 残留。均通过。
- 若用户仍有旧的孤儿 mpv：任务管理器结束 mpv.exe 即可；新代码不会再产生。
