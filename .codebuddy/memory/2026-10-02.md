## 修掉两个真实故障（都是用户报错后定位）
1. **用户报“无法创建图形窗口 / single application root window”**：根因是 `_main_impl` 里先用 `ttb.Style().theme_names()` 校验主题名，Style 单例提前绑定根窗口，随后 `ttb.Window(...)` 必然失败。改为 `_offline_theme_names()`（读 `themes.builtin.CURATED_THEMES` + `themes.legacy.STANDARD_THEMES`，不碰 Style）。
2. **WSS 连不上（日志：`create_connection() got an unexpected keyword argument 'proxy'`）**：本机实际是 websockets **13.1**（不是 requirements 里写的 15.0.1），13.x 会把 `proxy=`/`additional_headers` 透传给 `loop.create_connection`。新增 `jusic_core.ws_connect_extras()` 做版本能力探测（14+ 用 additional_headers / 13.x 用 user_agent_header / proxy 仅底层支持才传）。修完 CLI 与主题界面均实测连上房间并播放。

## 用户反馈「没有房间列表」→ 定位并修复（重要陷阱）
- 现象：新版界面左栏房间列表整个不可见。真实 mainloop 下诊断值：`paned sash0=0`、`left pane=1px`、`tree=1x1`。
- 根因：`_build_ui` 里用 `root.after(120, self._set_sash)` 设 `sashpos(0, 400)`，而 120ms 时 paned **还没映射、尺寸仍是 1x1**，Tk 把分栏位置截成 0 → 左栏压成 0 宽。离线手动 `root.update()` 的测试脚本因为时序偏后反而是正常的（所以之前没发现），只有真实 mainloop 会复现。
- 修法：改成 `_maybe_set_sash`，绑在 paned 的 `<Map>`/`<Configure>` 上，等 `winfo_ismapped()` 且 `winfo_width() > 100` 后再设一次（`_sash_done` 保证只设一次，之后尊重用户拖动）；同时给左 Labelframe 设 `width=380` 作为“请求宽度”兜底。
- 顺带加强房间面板：新增 `_rooms_hint_var` 提示行（`_refresh` 显示“正在获取房间列表…”、`_populate` 显示“共 N 个房间 · 双击进入”/“筛选出 x/y 个”/“未获取到房间：请检查网络后点刷新重试”），避免“空列表”被误认为界面坏掉；房间树列宽调整为 150/52/30/100。

## 界面内存对比实测（经典 vs ttkbootstrap 主题版）
- 方法：临时脚本 `%TEMP%\jusic_mem\mem_test.py`（`--console` + `JUSIC_GUI_PYW=1` 防 pythonw 重启，psapi `GetProcessMemoryInfo` 采样，`taskkill /F /T` 清场，含 mpv 内存用 `tasklist` 抓）；另有 `import_probe.py` 测纯导入开销。**不污染仓库**（全在 %TEMP%）。
- 结果（工作集，播放中稳定态，3 次采样一致 ±0.2 MB）：
  | 界面 | python 进程 | 提交 | mpv | 合计 |
  |---|---|---|---|---|
  | `jusic_gui.py`（经典 ttk） | **65.9→66.1 MB** | 40.0 MB | 57.0~57.2 MB | **≈123 MB** |
  | `jusic_gui_bootstrap.py`（litera 主题） | **76.2→76.3 MB** | 49.1 MB | 57.3~57.8 MB | **≈134 MB** |
- 差距 **+10.3 MB（+15.6%）**，来源定位：`import tkinter` 21.3 MB → `import ttkbootstrap` 34.0 MB（**+12.7 MB，且连带 `import PIL`**，Pillow 12.2.0）；再创建 `ttb.Window` 达 52.4 MB；python 空进程基线 18.0 MB。即主题版的增量几乎全在 ttkbootstrap(+Pillow) 的固定开销，而非我们的界面代码。
- 结论：低内存优先用经典版；主题版多约 10 MB（含 mpv 后总差约 8%），可接受。

## 打包脚本增加「主题界面版」产物（用户要求：build_exe*.bat 增加对 jusic_gui_bootstrap.py 的打包）
- 两个脚本现在默认**同时打包两个前端**，各新增开关 `-c/--classic`（只打经典）、`-t/--theme`（只打主题）、`-a/--all`（默认，显式 `-c`+`-t` 也当 both）。耗时/体积翻倍属预期。
- 产物命名（4 个）：
  - `dist\JusicRoomPlayer <VER>.exe` 57.6 MB、`dist\JusicRoomPlayerTheme <VER>.exe` 65.8 MB（1.3.0 实测）
  - `dist\JusicRoomPlayerPortable_<VER>.zip` 57.9 MB、`dist\JusicRoomPlayerThemePortable_<VER>.zip` 66.1 MB
- **关键坑：`--exclude-module PIL` 必须只用于经典版**。实测 `import ttkbootstrap` 会连带载入 Pillow（`'PIL' in sys.modules == True`），若照旧排除 PIL，主题版 exe 会在运行时崩。实现为 `:build_one` / `:build_dir_one` 子程序按 `BUILD_EXCLUDE_PIL` 变量拼 `--exclude-module PIL`。
- ttkbootstrap 2.2.3 自带 PyInstaller 钩子（`ttkbootstrap/_pyinstaller/hook-ttkbootstrap.py`，经 dist-info 的 `[pyinstaller40] hook-dirs` entry point 注册，收集 `ttkbootstrap.assets` 数据），无需手工 `--collect-all`。校验：主题版 exe 二进制内含 `ttkbootstrap`×102 / `PIL`×91，经典版为 0；两个 exe 冒烟启动 12s 不退出（`--volume 0`，taskkill 清场，无 mpv 残留）。
- `make_zip.py` 参数化：第 1 个参数=文件夹名（默认 `JusicRoomPlayerPortable_<ver>`，兼容旧调用），由 build_exe_dir.bat 传 `"%BUILD_STEM%"`。
- **踩坑 1（cmd 标签解析）**：新版单文件脚本首次运行时报 `The system cannot find the batch label specified - report_file`（第二次 `call :report_file` 失败）。用打桩脚本 + LF/CRLF 对照 + 小文件多轮测试**都无法复现**（间歇性）。处置：把产物体积报告改为**内联**（去掉 `call :report_file` 子程序），并把两个 bat 统一为 **CRLF 行尾**（`chcp 65001` + LF 是 cmd 解析器偏移异常的已知诱因）；之后 3 次真实运行均未再出现。
- **踩坑 2（我的编辑疏漏，导致目录版首跑失败）**：`make_zip.py` 只改了 `folder/target`（支持参数），`shutil.make_archive(..., base_dir=f"JusicRoomPlayerPortable_{ver}")` 仍是写死的经典名 → 打主题版时按经典文件夹名去 zip（该文件夹已被删）→ `FileNotFoundError` + "ZIP creation FAILED. Kept the folder instead"。已改为 `base_dir=stem`，直接用失败时保留的目录复测通过（ZIP 顶层 = 文件夹名，CRC 全好）。
- 其他：`build_exe.bat`/`build_exe_dir.bat` 步骤编号统一为 6 步（deps / version / mpv / 经典 / 主题 / 清理）；`build/` 打包后仍只剩 `version_info.txt`。
- 实测（VERSION 1.3.0，`-n`）：单文件 `build_exe.bat` **40s** → 经典 57.6 MB + 主题 65.8 MB；目录版 `build_exe_dir.bat` **30s** → 经典 ZIP 57.9 MB + 主题 ZIP 66.1 MB（ZIP 顶层=文件夹名、CRC 全好）。经典版比 9-30 的 62 MB 小 ~4.5 MB，推测是 hooks-contrib 2026.8 不再连带 `cryptography` 的 OpenSSL DLL（无害）。
- 冒烟验证：两个单文件 exe 各启动 13s 不退出；**主题版便携 ZIP 解压后的 exe 也启动正常**（`--volume 0`，`taskkill /F /T` 清场，无 mpv 残留）。`-c`/`-t` 单目标分支用打桩脚本验证（不实际打包，退出码 0、跳过分支正确）。
- 报告逻辑：单目标模式下只打印本次构建的产物（加 `if not defined DO_xxx` 守卫）；注意 `:build_dir_one` 会**先删除同名旧 ZIP**，所以用打桩方式跑目录版脚本会真的删掉 dist 里的 ZIP（本次踩到，重跑脚本已恢复）。
