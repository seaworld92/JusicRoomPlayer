## 踩坑与验证记录
- **ttk.Entry + 局部 StringVar 会被 GC**：`StringVar` 若是函数局部变量，函数返回后 Tcl 变量被删，
  控件文本变空。分享面板链接框改为 `state` 切换后直接 `insert` 文本。
- 自研二维码两处易错点（已修正）：
  1. 格式信息 15bit 的两处副本位序是**镜像**关系——副本一：(i,8) i=0..5、(7,8)=bit6、(8,8)=bit7、
     (8,7)=bit8、(8,14-i)=bit9..14；副本二：(8,size-1-i)=bit0..7、(size-15+i,8)=bit8..14，
     且 `(size-8,8)` 是固定深色模块不可被覆盖。
  2. 掩码评分 N3 用 7 位模式 `1011101` + 前后 4 个浅色（或贴符号边），N4 用 `floor(|深色占比%-50|/5)*10`
     （按 5% 分档，注意 45% 这类整倍数不是 0 分）。
- 验证方式（临时，非项目依赖）：把 `segno` pip 装到 `%TEMP%\qrlibs` 逐位对比矩阵 → 功能图形 0 差异、
  惩罚分逐掩码完全一致；再把 PNG POST 到 `api.qrserver.com/v1/read-qr-code` 回读，4 组固定 + 8 组随机用例全部一致。
  参考实现的填充码字会多插一个 `0x00`（无害差异），本项目按标准用 0xEC/0x11 交替填充。
- GUI 冒烟测试：伪造 `client.room` 后调 `_share_room()`，用 PIL ImageGrab 截图人工确认面板布局与二维码渲染正常。

### 点歌协议（抓 app.js 确认 + 真实房间实测通过）
- 搜索：`SEND /music/search {name, source, pageIndex, pageSize, sendTime}` → 服务端回 `SEARCH` 帧，
  `body.data = {data: [songs], totalSize: N}`。
- 点歌：`SEND /music/pick {name, id, source, quality, sendTime}`，`quality` = `320k`（标准）或 `flac`（高清）；
  成功后服务端推 `NOTICE`「点歌成功」并广播新的 `PICK` 队列。实测：搜索「告白气球」得到 20/306 首，点歌后进入队列 ✓。
- 其他同源指令（暂未用到）：`/music/top {id}`（置顶）、`/music/good/<id>`（点赞）、`/music/clear`、`/music/delete {id}`。

### 实测踩坑（重要）
- **搜索结果里没有 `source` 字段**（实测为 None）→ 点歌时必须用「当前所选音源」回填，不能依赖 song.source。
- **`fl`/`st` 在 `privilege` 子对象里**（`{"fl":1,"st":1}`），不在顶层；`album` 是**对象**（要取 `album.name`，
  直接 str() 会渲染出整个 dict）；`picture_url` 顶层与 album 内都有（本客户端不显示封面，保持低内存）。
- **`/music/delete` 对普通用户无效**：实测点歌后发 delete，队列不变（仍含该曲）→ 删歌/置顶/点赞应属房管权限。
  ⚠️ 因此那次实测在公开房 DEFAULT 里留下了一首「告白气球（Cover）- Xai小爱」，会自然播放掉，无法撤回。

## 命令行版（jusic_room_player.py）加点歌交互
- 新增命令：`p 关键字`（搜索歌曲）、`pick 序号 [flac]` / `点 序号 [flac]`（点歌，默认 320k，`flac`/`高清` 为高清）、
  `pn`（加载更多，pageIndex+1 追加）、`ph`（热歌榜 = 关键词 `*热歌榜`）、`src [音源]` / `音源 [音源]`（查看/切换，支持 `src QQ`、`src 2`）；
  另加 `--source` 启动参数（wy/qq/kw/kg/mg 或中文显示名，非法值回落 wy）。
- **同步等待设计**：`cmd_search_songs` 用 `threading.Event`（`self._search_ev`）等待后台线程的 `search` 事件，
  最长 `SEARCH_WAIT=12s`，超时给提示；`_on_event` 必须先写 `self._search_data` 再 `set()`，避免读到空数据。
  这样结果不会插在 `> ` 提示符里，输出干净。
- 房间序号与歌曲序号用途不同：点歌必须带 `pick` 前缀（`_resolve_index` 只认纯数字 → 无歧义）。
- 为两版共用，把歌曲字段工具下沉到 core：`song_unavailable()`（fl==0 或 st<0，顶层与 privilege 子对象都查）、
  `song_album()`（album 为对象时取 name）；GUI 的 `_song_unavailable`/`_album_label` 改为委托。
- 实测（真实房间 + 真实搜索，点歌拦截参数不发送）：`src` 系列、`p 晴天`（QQ 20 首）、`pn`（21–40）、
  `ph`（热歌榜 300 首）、`pick 1`/`pick 2 flac`/`pick 1 高清`/`点 3` 参数正确，`pick 999`/`pick abc`/`pick 1 xyz`/空参/未搜索 `pn` 均有友好提示。
