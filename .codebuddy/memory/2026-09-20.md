## 音量改为即时生效（jusic_core.MpvEngine + GUI）
- 需求：GUI 音量滑块原来是"下一首生效"（只改 `engine.volume`，仅用于下次启动 mpv 的 `--volume`）。
- 方案：每首新歌启动 mpv 时加 `--input-ipc-server=<唯一地址>`，音量变化通过 mpv IPC 下发
  `{"command":["set_property","volume",N]}`。地址：Windows `\\.\pipe\jusic-mpv-<pid>-<seq>`，
  其它平台 `<tempdir>/jusic-mpv-<pid>-<seq>.sock`。
- 实现要点（jusic_core.py）
  - `MpvEngine.__init__` 启动常驻守护线程 `_pump_loop`（name=jusic-mpv-volume）：只在
    `self.volume != 已下发值` 时下发，`time.sleep(0.02)` 合并拖动中间值；失败重试 ≤40 次（50ms 间隔），
    用 `self._ipc_seq`（每首 +1）判断换曲并重置状态，`running()` 为假时不再重试。
  - `_ipc_push()`：**一次性连接**（连接→写→读回执→关闭），单线程使用。经验教训：同一 Windows
    命名管道句柄上并发读+写会**永久阻塞**（实测 reader 线程 + 主线程写，写卡死 → 必须一次一连接）。
  - `set_volume()` 只改 `self.volume` 并 `self._ipc_wake.set()`，**永不阻塞调用方**（GUI 线程安全）。
  - `_stop_locked()` 清空 `_ipc_path`（POSIX 顺带删除 socket 文件）。
- 实测（Windows + mpv 0.41，lavfi 与真实后端房间都试过）
  - 播放中 set_volume 即时生效耗时 ~0.02s（真机联调 0.125s 含探针重试）；300 次连续下发 0.21ms/次、
    0 失败、mpv stderr 为空、无内存/句柄异常；换曲后新进程同样即时生效；停止后调用不报错、无残留进程。
