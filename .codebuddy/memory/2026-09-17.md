## 实测 jusic_gui.py 运行内存
用户要求确认 GUI 版运行占用内存。

方法与结果（Windows 11，源码运行 `python jusic_gui.py --console --volume 0`，进入 DEFAULT 房播放中稳态，WorkingSet）：
- python(tkinter) 进程：54.6 MB（未播放）→ **稳态 55.3 MB**（峰值 55.4）
- mpv 进程：启动 44.6 MB → 随缓冲增长到 **稳态 57.3 MB**
- **合计 ≈ 112.6 MB**
- 关闭窗口（WM_CLOSE）后两进程均退出，无 mpv 残留。

对比：命令行版此前实测 python 37.5 + mpv ~53 ≈ 90 MB；GUI 多出约 18 MB（tkinter）。
注意：打包 exe（PyInstaller onefile）首次启动需解压内置 mpv 到临时目录，会有短暂额外磁盘/内存开销；onedir 版则启动更快、内存表现与源码接近。

测量脚本模式：ASCII temp runner 启动 GUI(--console 保持单 python 进程)，PowerShell 按 CommandLine 过滤 python 进程 + Get-Process mpv 采样 WorkingSet64，EnumWindows+WM_CLOSE 优雅关闭。

## 新增切歌功能（GUI 按钮 + core 指令发送）
- 后端协议：仅 `@MessageMapping("/music/skip/vote")`（无参数）；行为=广播 CHAT「投票切歌」；被禁切且非管理员→NOTICE「禁止切歌」；管理员→直接切歌 NOTICE「切歌成功」；普通成员→计票，达 voteRate 后切歌（NOTICE「x/y 投票成功」）。另有 `/music/banswitch/{ban}` 仅房管可用。
- **关键技术坑（重要）**：SockJS WebSocket transport 下，客户端→服务器的 STOMP 帧必须包在 **JSON 数组**里发送（`json.dumps(["CONNECT\n...\x00"])`，无 'a' 前缀）；发明文 STOMP 帧会被服务端以 `c[1011]` 立即关闭连接。已实现 core.stomp_frame() + RoomClient.command(destination,body)/skip_vote()，_session_loop 连接后自动发 STOMP CONNECT（accept-version 1.1,1.0; heart-beat 0,0）。
- GUI：当前播放区新增「切歌（投票）」按钮 → _skip_vote()。
- 验证：core 层发送后收到 NOTICE「1/19 投票成功」「有人希望切歌…」且连接不断；GUI 日志显示本地请求+服务端 CHAT/NOTICE 反馈 ✔。README/.pyw 已同步。
- 备注：未设置昵称时聊天显示 IP（服务端按 IP 生成昵称），如需可后续用 STOMP `/setting/name` 设置。
